## Context

參見 [proposal.md](./proposal.md) 的 Why。本次改動只處理既有 React／TypeScript 前端的五頁決策體驗，不改指標模型與 API。現況已有可保留的基礎：非循環檔案夾導覽、hash 路由、單一整頁捲動、依職業／分頁保存閱讀位置、跨頁焦點定位、dialog 關閉回焦，以及明確標示的缺值。

實際以 1280 × 720 走查五頁後，主要限制如下：

- `App.tsx` 的全域脈絡只顯示「目標族群 18–35 歲」，但現有求才數字是全年齡資料；小字警語不足以抵消頁首造成的誤解。
- `FolderPages.tsx` 的「排名」同時呈現 01／02／03 與「Risk 尚未核定，暫不做風險排名」，視覺訊號與文字聲明互相衝突。
- `DecisionPanels.tsx` 的跨頁 CTA 會把使用者帶到尚不存在的排名或政策內容，且「會議草稿／監測摘要／政策報告」命名不一致。
- `EvidenceReview.tsx` 將不可完成後續動作的核取方塊放在已核對證據之前，形成互動死路。
- `folderDashboard.css` 的主要分頁轉場為 420ms，並搭配 `FolderWorkspace.tsx` 的 460ms 固定計時器；快速切換時回饋偏慢且難以中斷。
- `indicatorHelp.css` 只有指標抽屜進場動畫，其他詳情直接出現，關閉則全部直接消失。

### 視覺方向

保留目前「政策工作檔案夾」的辨識度，介面氣質採政府研究桌面：沉穩、精確、留白受控，不新增漸層、玻璃效果或裝飾動畫。

- 色彩 tokens：`Ink #163746`、`Folder #104B63`、`Canvas #F7F8FA`、`Paper #FFFFFF`、`Soft #EDF3F6`、語意色 `Positive #17634D / Negative #A73535`。
- 字體：沿用本機可用的 `Microsoft JhengHei`／`Noto Sans TC`／`Segoe UI` 字型堆疊，避免比賽環境載入網路字型失敗。
- 字級：頁面問題 24–28px／700，直接答案 18–20px／700，內文 15–16px／400–500，metadata 12–13px／500；數字使用 tabular numerals。
- 間距：以 8px 為基本節奏；頁內主要段落 16–24px，卡片內距 14–18px，避免每層容器都加 24–32px 造成空間鬆散。

```text
[目前職業] [分析期間] [來源狀態]
[政策目標：18–35] [目前資料：全年齡求才｜不可直接代表青年]
[ 指標 | 排名 | 診斷 | 論證 | 政策 ]

┌─ 檔案夾：頁名／成熟度 ───────────────────────────┐
│  本頁要回答的問題                                  │
│  直接答案／誠實空狀態                [主要下一步]   │
│  ───────────────────────────────────────────────  │
│  支持內容（比較、證據鏈或政策選項）                  │
│  [查看來源／方法／限制]                              │
└───────────────────────────────────────────────────┘
```

設計原則：結果先於 provenance；一頁一個主要問題；一個狀態只有一套名稱；能做的動作比不能做的按鈕更醒目；空狀態也必須提供有價值的產物或下一步。

## Goals / Non-Goals

**Goals:**

- 讓五頁在首屏形成可連續理解的決策敘事，而不是五組彼此獨立的資料卡。
- 讓所有排序、診斷、證據與政策用語符合實際 readiness，不讓 UI 比資料走得更快。
- 以共用 presentation state 控制跨頁狀態、CTA 與空狀態，減少文案互相矛盾。
- 在不增加前端框架依賴下，改善 1280 × 720、390 × 844、200% 縮放與鍵盤使用。
- 將高頻分頁轉場縮短並可中斷，保留檔案夾移動所需的空間因果。

**Non-Goals:**

- 不核定或修改 S、A、B、C、H、D、Risk 公式與門檻。
- 不補造青年細分、AI 暴露、產業映射、專家證據或政策資料。
- 不在本變更串接 AI 檢索、後端批次核對或政策生成服務。
- 不重命名五個頂部分頁、不改成 wizard、不啟用滾輪換頁，也不改變非循環邊界。
- 不全面重做 landing page、品牌識別或頁首功能。

## Decisions

### 1. 建立單一 presentation state，而非讓各頁自行推測成熟度

在現有 analysis model 之上新增唯讀的前端呈現層，統一導出：

- `populationScope`：政策目標、資料涵蓋與是否 mismatch。
- `riskReadiness`：可正式比較、方法待核定、資料不足。
- `evidenceReadiness`：已核對關係、候選來源、可否送交核對。
- `policyReadiness`：監測摘要、可比較政策、可輸出報告。
- 各頁 `primaryAction`：標籤、目的分頁、焦點目標與 unavailable 原因。

各頁只消費同一組狀態，不自行拼接「待核對」或猜 CTA。這個呈現層不得計算新的政策數值；排序只使用 model 已提供且有來源的欄位。

替代方案是直接在五個 JSX 元件內分別修字。未採用，因職業或後端 readiness 改變後容易再次出現「按鈕承諾 A、落地卻是 B」的漂移。

### 2. 保留「排名」標籤，但讓頁內排序名稱完全誠實

頂部分頁維持使用者已確認的「排名」。頁內採雙模式：

| 狀態 | 頁內標題 | 排序 | 序號意義 |
|---|---|---|---|
| Risk 未核定 | 職業求才變化比較 | 求才年變化，明示升／降冪 | 此排序下的位置，不是 AI 風險名次 |
| Risk 可比較 | AI 就業風險排名 | 正式 Risk | AI 風險名次 |

Risk 未核定時不再以「— / 100」占據左側主視覺，改成一列「Risk 尚不可比較」狀態與缺口；主要空間交給實際可比較的求才變化。序號由目前排序即時計算，不沿用來源陣列順序。

替代方案是直接把頂部分頁改名「比較」。未採用，因這會違反目前已確認的五個標籤與既有路由語意；雙模式能保留入口名稱並避免假排名。

### 3. 以頁面問題重組內容，不以資料結構平鋪

五頁的主敘事如下：

| 分頁 | 要回答的問題 | 首屏核心 | 主要下一步 |
|---|---|---|---|
| 指標 | 有哪些訊號、缺什麼、如何形成 Risk？ | 已知觀測＋`A/B/C → S`、`S/H → Risk`、D 獨立的依賴關係 | 比較職業求才變化或查看正式排名 |
| 排名 | 目前能用哪個已核對維度比較職業？ | 排序依據、職業列表、選取職業摘要 | 理解這項變化目前能／不能說明什麼 |
| 診斷 | 觀測、可能解釋與不能下的結論是什麼？ | 已知／未知／可能解釋／下一步核對 | 核對這項觀測來源 |
| 論證 | 判斷由哪些來源支持或限制？ | 判讀 → 證據 → 角色 → 限制 | 整理監測摘要或查看已核對政策 |
| 政策 | 現在能帶進會議的是什麼？ | 依成熟度顯示監測摘要或政策比較 | 預覽同名產物 |

指標頁不再讓六個「—」卡片成為視覺主角，而是用分組或簡潔流程呈現輸入訊號、推導結果與獨立觀測。詳細公式仍由既有抽屜承接。

診斷頁把重複的 109,342 → 93,997／-14.03% 合併為單一觀測，其餘空間用來表達不能推論 AI 因果與所需補證。原始 `demand-2024` 等 ID 只留在詳情。

替代方案是只縮小現有卡片。未採用，因密度問題來自資訊層級錯置，不是單純尺寸過大。

### 4. 論證先顯示已核對關係，候選來源只在有出口時可選

`EvidenceReview` 分成兩區：

1. 「目前判讀的證據鏈」：先列 claim、來源、支持／限制角色、適用範圍與詳情。
2. 「待補與待核對來源」：服務未串接時是可閱讀／逐筆開啟的候選清單；提供可完成送交流程後才改成 checkbox 批次操作。

永久 disabled 的「用 AI 核對」不再作為主操作；改成狀態說明與一個可完成的替代行動。`disabled` 按鈕無法由鍵盤取得焦點，其 unavailable 理由也不應只靠 `aria-describedby` 綁在該按鈕上。

替代方案是保留核取方塊並新增 tooltip。未採用，因 tooltip 不能補足沒有結果的工作流，也不利觸控與輔助科技。

### 5. 政策頁以成熟度切換「監測摘要」與「政策選項」

零政策資料時，主標題改為「目前可整理：監測摘要」，主 CTA 與輸出標題都使用「預覽監測摘要」。摘要只能包含已核對觀測、限制、缺口與下一步，不宣稱已有政策建議。頁面另提供「回論證查看政策證據缺口」。

當政策選項通過既有品質檢查後，才顯示「比較政策選項」、選取控制與「預覽政策討論草稿」。政策卡首層只放名稱、目標對象、核心機制、證據狀態與是否納入；成本、合作方、KPI、限制與引用用展開層呈現。列表採容器寬度決定一至兩欄，不在 920px 內容區硬塞三張長卡。

替代方案是無資料時只顯示空白空狀態。未採用，因現有快照仍能形成有價值且不越界的監測摘要。

### 6. 全域 context strip 同時呈現政策目標與資料涵蓋

將目前單句「目標族群 18–35 歲」改為兩個平行欄位：

- `政策目標：18–35 歲`
- `目前資料：全年齡新登記求才`，附「不可直接代表青年」狀態

這項提示在五頁常駐；頁內只在推論邊界相關處簡短引用，避免每張卡重複長警語。若未來資料真正提供 18–35 歲切片，呈現層可將 mismatch 改為一致狀態，不需修改頁面文案。

### 7. 視覺密度以共用區塊節奏收斂

保留 Folder `#104B63` 與黑色作用中分頁，不新增第二套強色。每頁首屏最多包含：頁面問題、直接答案／空狀態、一個主 CTA、第一組核心內容。次要 provenance 入口統一置於內容尾端或詳情列。

桌面內容以 2 欄為上限；3 欄僅用於短、可掃讀且高度接近的指標項。390px 時改為單欄緊湊列，隱藏側邊檔案夾；Risk 不可用時以單行狀態取代大卡。整頁保留唯一垂直 scroll owner，內容高度繼續由 ResizeObserver 推動 folder shell 成長。

### 8. 將 motion 調整為短、可中斷、同一語法

不新增 motion library，沿用 CSS transition 與目前的 workspace 狀態機：

- 高頻分頁／側夾：`240ms cubic-bezier(.32,.72,0,1)`；作用中標記與 folder shell 共用 token。
- 列表選取、按鈕狀態與內容淡入：`160–180ms ease-out`。
- 詳情抽屜：指標裝置開啟與關閉各 `220ms cubic-bezier(.32,.72,0,1)`；鍵盤啟動、reduced-motion 或程式化焦點跳轉不等待空間動畫。
- 右下通知：180ms opacity＋8px translate 的進退場；loading → success／error 只做短淡化，spinner 維持 linear。

移除 `FolderWorkspace` 與 CSS duration 的 460／420ms 雙重常數，改由同一 token／transition completion 清理 outgoing 狀態；新的輸入到來時取消前一個清理流程，以最新目標為準。所有 hover 位移只在 `(hover:hover) and (pointer:fine)` 下生效。

首次沒有已保存偏好時，以 `prefers-reduced-motion` 決定動態；使用者手動切換後保存其選擇。reduced 模式移除 translate／scale，不影響內容更新、focus 與 URL。

替代方案是將所有轉場直接關閉。未採用，因檔案夾的空間位移能解釋分頁關係；問題是目前過慢與不一致，而不是動畫本身。

### 9. 測試以使用者承諾與 viewport 結果為主

保留現有單元測試，新增以下層級：

- presentation state 單元測試：Risk null／ready、政策零／有資料、evidence action unavailable／available、population mismatch。
- React 行為測試：CTA 與落地標題同名、排序序號正確、candidate 無 dead-end checkbox、抽屜回焦、非作用中 panel 不可聚焦。
- Playwright：1280 × 720 五頁首屏、390 × 844、200% zoom、快速連續分頁、pointer／keyboard／OS reduced-motion、zero-policy 與 null-Risk 快照。
- 可存取性檢查：tab／tabpanel 關係、方向鍵與 Home／End、狀態非只依色彩、通知朗讀與 disabled 替代內容。

截圖測試只驗穩定終態；互動測試另驗中斷轉場後 URL、選取標記與內容一致。

### 10. 修正 landmark、可存取名稱與對比，不只補 ARIA

把跳至主要內容連結移到 DOM 的第一個可聚焦位置，並由 App 提供唯一 `main` 包住 FolderWorkspace 的作用中內容。指標與診斷的主要 panel 不再使用 `aside`；只有額外解釋才使用 complementary landmark。

指標卡保留可見文字作為名稱，使用 description 關聯「待核對／資料不足／尚無核定分數」，避免目前的長 `aria-label` 吃掉狀態。排名列採有欄位關係的表格／grid 語意，或為每列提供完整可存取描述；目前職業加上「目前選取」文字或圖示，不只改背景色。

提高現有小字 token 的明度對比：目前多處灰字只有約 3.7–4.1:1，需統一到一般文字 4.5:1 以上。手機提示改為「在標題列左右滑動」且至少 12px，主要觸控區維持 44 × 44px。

替代方案是僅新增更多 ARIA 屬性。未採用，因 landmark 誤用、文字對比與 dead-end disabled 控制是結構及視覺問題，ARIA 無法修正。

## Risks / Trade-offs

- [保留「排名」標籤仍可能讓人先入為主] → 在頁內標題、排序選擇與序號說明三處使用同一可驗證依據；Risk 未核定時不顯示 `/100`。
- [更多 readiness 分支增加前端複雜度] → 所有分支集中於 presentation state，以 fixture 測試，不散落在五頁 JSX。
- [常駐人口範圍提示占用首屏] → 使用短欄位＋狀態標籤；完整限制放詳情，但不得把 mismatch 隱藏。
- [縮短動畫後檔案夾可能失去滑順感] → 保留具自然減速的 drawer curve，Playwright 以連續切換與中途狀態驗證，不以更長 duration 製造滑順。
- [政策卡漸進揭露可能增加一次點擊] → 首層只保留真正用於比較的欄位，展開狀態沿用目前職業／頁面的閱讀狀態保存。
- [前端替代排序被誤認為新分析模型] → 僅排序已核對的求才年變化，顯著標示「非 AI 風險排名」，不產生新分數。

## Migration Plan

1. 先加入 presentation state 與 fixture 測試，不改畫面輸出。
2. 更新全域資料範圍提示與共用狀態元件，驗證五頁用語一致。
3. 依「指標 → 排名 → 診斷 → 論證 → 政策」逐頁替換資訊結構與 CTA；每完成一頁即跑既有行為測試。
4. 最後調整共用版面與 motion tokens，避免內容與動畫同時大幅變動而難以回歸。
5. 以 1280 × 720、390 × 844、200% zoom 走完完整流程，保存視覺驗收結果並跑正式 build。

若需回退，可逐頁退回原 presentation component；資料模型、hash route 與 API 未變，因此不需要資料遷移或後端 rollback。
