## Why

目前「指標 → 排名 → 診斷 → 論證 → 政策」已具備完整的五頁骨架與一致的檔案夾導覽，但部分頁面的名稱、資訊優先序與可完成動作仍不一致：例如 Risk 尚未核定時，「排名」頁仍以排名語氣呈現；「論證」頁可勾選來源，卻沒有可完成的後續驗證動作；「政策」頁則以不可用功能與空狀態為主。這些落差會讓使用者需要先理解系統限制，才知道下一步能做什麼，削弱政策決策流程的連續性。

本變更將在不修改指標公式、資料內容與後端契約的前提下，重新整理五頁的任務層級、狀態語意、內容密度、跨頁行動與動態回饋。目標是在 1280 × 720 的展示環境中，讓使用者進入每一頁後能快速回答「現在知道什麼、依據是什麼、下一步做什麼」，同時保留既有的一頁式 Dashboard、五分頁檔案夾隱喻與可直接跳頁的操作方式。

## What Changes

- 建立五頁一致的閱讀骨架：頁面問題、直接答案、支持證據、限制與單一主要下一步。
- 統一「已核對、待核對、資料不足、尚未串接」等資料與功能狀態，所有狀態同時使用文字與圖示，不只依賴顏色。
- 將「政策目標族群」與「目前資料涵蓋範圍」並列呈現；當全年齡求才資料尚不能代表 18–35 歲青年時，常駐揭露此差距，避免誤讀。
- 將「政策目標族群」與「目前資料涵蓋範圍」並列呈現；當全年齡求才資料尚不能代表 18–35 歲青年時，常駐揭露此差距，避免誤讀。
- 改善「排名」頁的誠實呈現：Risk 未核定時，明確使用可驗證的排序依據（預設為求才年變化），並標示這不是 AI 風險排名；Risk 完整後才切換為正式風險排名。
- 將「診斷」頁整理為已知、未知、可能解釋與下一步核對的證據鏈，避免重複同一數字，並將原始欄位 ID 等工程資訊收進詳細資料層。
- 將「論證」頁區分為已核對且用於判讀的證據，以及尚待核對的候選來源；只有存在可完成的批次動作時才顯示勾選控制。
- 將「政策」頁改為依證據成熟度漸進呈現：資料不足時仍提供可用的監測摘要與補證路徑；證據足夠時再提供政策選項、比較與報告輸出。
- 收斂各頁的主次 CTA，形成「查看指標 → 比較職業 → 理解診斷 → 核對論證 → 整理政策」的連續路徑，但不鎖住直接跳頁。
- 提升首屏資訊密度與視覺層級，維持既有配色、字體與檔案夾造型，避免重做品牌視覺。
- 定義分頁、側邊抽屜與通知的動態規格，包括可中斷、低於 300ms 的主要轉場、退出動畫，以及 `prefers-reduced-motion`／手動關閉動態效果的降級行為。
- 補足鍵盤焦點、語意標記、200% 縮放、窄螢幕與狀態朗讀等驗收條件。

## Capabilities

### New Capabilities

- `five-page-decision-experience`: 定義五個政策決策分頁的一致資訊架構、真實狀態呈現、跨頁任務銜接、漸進揭露、響應式、無障礙與動態回饋。

### Modified Capabilities

- 無。現有 OpenSpec 尚未封存主規格；本能力會補充現行變更中的產品流程規格，而不改寫其資料模型或 API 契約。

## Impact

- 主要影響 `frontend/src/features/folder-dashboard/` 下的頁面容器、五頁內容元件、共用狀態元件、指標說明抽屜、通知與樣式。
- 可能需要調整既有 UI 測試、鍵盤操作測試、路由／分頁切換測試與 1280 × 720 視覺回歸測試。
- 不變更 A／B／C／H／D、S、Risk 公式，不新增或偽造資料，不改變來源核對規則。
- 不要求本次變更新增後端端點；尚未串接的功能必須提供誠實且可行的降級流程。
- 保留既有五個標籤名稱「指標、排名、診斷、論證、政策」、hash 路由相容性、44px 導覽列與非循環檔案夾切換。
