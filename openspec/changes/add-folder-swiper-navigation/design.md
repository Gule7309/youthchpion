使用者明確要求預設開啟。本節取代文件先前「完全跟隨系統 reduce」的描述：僅檔案夾工作區預設 full，不需變更 Windows 設定；畫布下方提供「動畫效果」開關，關閉立即定格。以 localStorage 的 youthlm.folder-motion 保存 full/reduced，無效值或讀取受限則預設 full，寫入受限仍維持本次選擇。此偏好按網站 origin 保存，不跨 localhost／127.0.0.1 或不同連接埠同步。其他介面仍保留系統的減少動畫規則。

新增回歸測試，瀏覽器已實測 system reduce=true 時主外夾仍有 0.42s 過渡；關閉後 0s，重新整理仍關閉；320px 開關為 44px 高且無水平溢出。未改資料、API、分頁順序或 wheel。原生 200% 仍待補驗。


本文件為五頁檔案夾 UI 的設計規格，狀態為「待審閱，尚未實作」。動機與範圍見 [proposal.md](proposal.md)；可驗收行為見 [spec.md](specs/folder-swiper-navigation/spec.md)。

已確認的需求：

- 五頁固定為「指標、風險、診斷、論證、報告」。
- 頂部導覽與側邊收合檔案夾都可切換，整體重視滑順感。
- **不循環**：指標是第一頁、報告是最後一頁。
- **滾輪只閱讀當頁**，不換頁。

現況依 repo 程式檢視：`App.tsx` 是 React／TypeScript 單頁，使用四個 hash 錨點、三欄內容與下方研究／政策區。`policyDashboard.css` 已有淺色樣式、圖示及減少動態效果分支。`ReviewDashboard.test.tsx` 與舊頁測試合計 11 項；此數字是既有測試範圍，不代表新五頁功能已通過。

資料方面，`verifiedSnapshot.ts` 有三職業 2024／2025 年整體求才真實值，A/B/C/D、正式 H／Risk 與政策報告仍有缺口。`refreshDashboard` 的既有 API 契約仍不相容新版模型。因此本案重組閱讀與導航，不順便修模型或假裝補齊後端。

## Goals / Non-Goals

**Goals:** 將內容與導覽拆開，讓五頁共用一份職業／版本脈絡；用輕量狀態與可中斷動畫完成檔案夾切換；在文字放大、長內容、鍵盤與觸控下維持可讀。

**Non-Goals:** 不製作五份彼此獨立的資料狀態，不新增前端 Risk 計算器；不把系統做成必須依序完成的 wizard；不在本提案中建置或部署 UI。完整政策內容與可下載報告不列為這次介面改版的完成條件。

## Decisions

### 1. 五頁各自回答一個問題

| 頁面／網址 | 使用者想知道什麼 | 主要內容與既有對應 | 現有資料不足時 |
|---|---|---|---|
| 指標 `#indicators` | 模型看哪些訊號？ | A/B/C/H/D 小型構面、S 結構性暴露；目前核心指標與計算說明 | `—`、缺口、方法待核定；公式可讀但不產生假值 |
| 風險 `#risk` | 哪些職業值得關注？ | 目前職業比較列表、Risk 區、真實求才趨勢；點職業列更新全域選取 | 不做 Risk 排名；顯示已核對招募變化及口徑限制 |
| 診斷 `#diagnosis` | 為什麼有這個判斷？ | 目前診斷區、相關構面、其他解釋與判讀限制 | 顯示「證據不足」，不靠職業名稱猜類型 |
| 論證 `#evidence` | 有什麼資料與研究支持？ | 研究來源、機構／作者、摘要、支持的判斷、限制、核對狀態與原文入口 | ILO／AIF 僅按現有方法／背景來源呈現，不冒充職業專屬背書 |
| 報告 `#report` | 可評估哪些政策方向？ | 目前政策區、可用選項、依據、限制、報告入口；未來接完整報告 | 保留可閱讀的限制與待辦，生成按鈕停用並附原因 |

頁首共用一個有明確標籤的職業選取控制項，各頁都可直接切換職業。風險頁的比較列是同一選取狀態的另一入口，不建立另一份獨立篩選。資料來源／清洗／估算／計算仍由共用詳情面板承載，論證頁提供集中入口。

選擇理由：沿用現有內容可先驗證新 UI，不等待新 API。相比將五頁全部塞入同一個大面板再加分隔線，每頁一個問題更容易導讀。

### 2. 視覺結構：展開的檔案夾，而非五個網站

```text
YouthLM ／ 目前職業 ▾                  資料期間・快照狀態・更新

           指標    風險   [診斷]    論證    報告

 指標  風險     ┌─ 診斷 ──────────────┐     論證  報告
 收合  收合     │ 標題／當頁操作       │     收合  收合
               │ 目前職業的可讀內容   │
               │ 當頁垂直閱讀捲動     │
               └─────────────────────┘
```

以上為第三頁示意；首尾不為了對稱補出不存在的目標。

- 頂部導覽採參考圖的長膠囊，選取項為近黑色底、白字；未選取為淡灰藍底、深色字。斜切分界屬裝飾，不切到文字與點擊範圍。
- 檔案夾採深藍綠外框、圓角與左上凸出的標籤；內部閱讀區採白色或極淡藍白，避免整份長報告都壓在深色大底上。
- 頁首保持簡短，不恢復已要求移除的長標題／宣傳段落。原本直式 rail 移除，避免有兩套用途相同的主導航。
- 共用資料期間及「已核對快照／非即時更新」在換頁後仍可見，不以選取黑色代表風險高低。

設計起點（提案值，可在 UI 驗收時微調，不是從參考圖精確取樣）：

| 項目 | 起始規格 |
|---|---|
| 畫布／導覽底 | `#F7F8FA`／`#DEE8ED` |
| 檔案夾外框／導覽選取 | `#104B63`／`#111719` |
| 內文／次要文字 | `#24343D`／`#5E707C`；實作時檢查文字對比 |
| 頁內標題／本文／註記 | 24–28px／16px、行高約 1.65／14px；不以縮小至 10px 解決擠壓 |
| 桌機分頁文字／手機分頁文字 | 18–20px／14–16px；五頁名稱不省略 |
| 內容區間距／內距 | 12–16px／桌機 20–24px、手機 16px |
| 圓角 | 外夾約 28px、內頁約 20px；窄版可收至 16px |
| 點擊範圍 | 頂部分頁、側邊切換及主要圖示按鈕至少 44 × 44px |

選擇理由：參考圖用於形狀、比例與切換概念，不逐像素照搬空白深色矩形。閱讀區仍保留前一版的乾淨與清楚字級。

### 3. 收合檔案夾的排列與邊界

桌機每側最多兩個最近分頁，較遠頁使用頂部導覽直達。此為本提案的排版選擇，讓首尾仍能保留足夠閱讀寬度，不要求把另外四頁全擠在同一側。

| 目前展開 | 左側，由外至內 | 右側，由內至外 |
|---|---|---|
| 指標 | 無 | 風險、診斷 |
| 風險 | 指標 | 診斷、論證 |
| 診斷 | 指標、風險 | 論證、報告 |
| 論證 | 風險、診斷 | 報告 |
| 報告 | 診斷、論證 | 無 |

- 中央展開區固定置中；側槽預留位置，缺少一側不使中央突然移位。收合目標以距離由近到遠降低高度，保持清楚的前後層次。
- 收合項是獨立按鈕：有短頁名、方向與頁序的可及名稱，例如「開啟報告，第 5 頁，共 5 頁」。縮窄時可用直排短名，但不能只剩不具名的色條。
- 每個側邊目標的可點面積不重疊；裝飾背景不攔截點擊。Hover／焦點只微幅提亮或抬升，不直接換頁。
- 無上一頁／下一頁時不顯示對應目標。也不以「報告」放在指標左邊的方式補對稱。

未採方案：首尾循環違反已確認需求；在首頁右側排四個微小可點層會降低辨識與閱讀寬度；純左右箭頭則不符合使用者要點收合檔案夾的感覺。

### 4. 滑順感來自換頁過渡，不接管滾輪

| 動作 | 視覺規格 |
|---|---|
| 切至後頁 | 舊夾往左收合，目標由右展開；頁內文字僅平移／淡入，不橫向壓扁 |
| 切至前頁 | 以上方向相反 |
| 遠距直達 | 依索引方向一次過渡到目標，不逐頁播放 |
| 選取底色 | 與頁面共用目標，平移至所選分頁 |
| 快速改選 | 從當前可見位置銜接到新目標，舊完成事件失效，最後一次選取勝出 |
| 減少動態效果 | 直接定格在目標；無位移、縮放、慣性與平滑捲動 |

動畫起始參數：主要過渡 420ms（驗收調整範圍 350–450ms），`cubic-bezier(0.22, 1, 0.36, 1)`；內容淡入約 160–200ms；hover 約 160ms。避免過衝彈跳、旋轉、重度景深與大範圍模糊。這些是設計目標，低效能設備的實際幀率須在實作時量測，不能用文件宣稱已達成。

中央舞台採穩定尺寸與獨立內容閱讀區。主要動畫用 transform／opacity；背景檔案夾外形與內文分層，不能對整棵文字 DOM 做 `scaleX`。最多保留進場／退場兩份視覺內容，退場立即不可互動並從輔助閱讀順序移除。

換頁控制狀態區分目標頁與退場頁。新選取立即更新唯一的語意目前頁，進場內容使用同一目標；完成回呼以過渡序號驗證，過期回呼不能反向修改分頁。移除元件、尺寸改變、`transitioncancel` 或媒體偏好變更時清理過渡，沒有動畫事件也能落在正確狀態，不能靠固定延遲鎖導航。

選擇理由：單純 `scroll-behavior: smooth` 只處理捲動，無法表達檔案夾的收合展開。全頁慣性捲動套件會改變使用者已確認的滾輪用途，因此不採用。

### 5. 輸入方式與手勢衝突

| 輸入 | 操作 |
|---|---|
| 點頂部分頁 | 直達該頁；點目前頁不重設狀態 |
| 點側邊收合夾 | 直達該側夾代表的頁，不限於一頁距離 |
| 滑鼠／觸控板 wheel | 只做原生捲動；水平 wheel 也不轉為切頁 |
| Ctrl + 滾輪、多指縮放 | 保留瀏覽器功能，不接管 |
| 頂部左右鍵 | 只移動焦點，首尾夾限；Home／End 到首尾 |
| Enter／Space | 啟用已聚焦的頂部分頁或側邊按鈕 |
| 觸控標題手勢區 | 左滑下一頁、右滑上一頁；一次最多一頁 |
| 觸控內文／圖表／表格／modal | 原生閱讀或該元件操作，不做頁面手勢 |

手勢區位於檔案夾標題中的非互動空白範圍，至少 44px 高，提供小字提示「左右滑動切換分頁」；按鈕、選單不屬於手勢區。採單一觸點：位移需至少 48px 且水平位移至少為垂直的 1.5 倍才成立；未達、取消、多指或邊界均不換頁。手勢成立後抑制同一次觸控產生的誤點擊。標題以外的內文不裝全域 swipe 攔截器。

這些門檻是可測試的起始方案；相比在整個頁面攔截所有橫向動作，限定手勢區能保留文字選取與未來圖表操作。桌機不要求按住整頁拖曳，避免干擾文本複製。

### 6. 分頁與閱讀狀態

規劃以少量 UI 狀態管理，不改後端資料模型：

- 頁面定義只保留穩定 ID、順序、名稱與圖示，不以畫面文案當作 key。
- 全域共用：目前分頁、選取職業、完整快照 ID、刷新狀態及共用詳情入口。
- 閱讀狀態以 `(快照 ID, 職業代碼, 分頁 ID)` 區分，保存捲動位置及一般展開項目；只在本次工作區記憶體保留，不宣稱關閉瀏覽器後仍保留。
- 選取其他分頁不重設職業或資料；選取另一職業不把人帶回風險頁。第一次讀取一組新 key 從頂部開始；返回已讀組合恢復該組合的位置。
- 不以所有頁面永久可見的方式保存狀態。可以保留資料／展開 state，但隱藏頁不得有焦點、事件攔截或重複 live announcement。
- Modal 是短暫狀態，不按頁長期保存；返回分頁不自動重開先前關閉的來源面板。

主要閱讀區為單一垂直 scroll container，以內容自然高度形成捲動範圍；切頁前保存來源位置，目標 layout 完成後直接恢復目標位置，不用額外平滑捲動從 0 飛到舊位置。頁內表格等必要局部橫捲為例外。

選擇理由：每頁共用一個 scrollTop 會使短頁落在底部；按每個職業／版本分別保存，可避免換職業仍停在不相干的段落。無需為此引入資料庫或 localStorage。

### 7. 響應式與內容高度

| 可用視窗 | 排版方案 |
|---|---|
| 寬度 ≥ 1200px | 中央內容最大約 1080px，每側最多兩個收合夾；槽內目標寬 44–56px，留可辨識間隔 |
| 768–1199px | 每側只顯示最近一個收合夾；頂部保留五頁，中央擴展閱讀寬度 |
| 寬度 < 768px | 隱藏側邊夾，保留檔案夾標題形狀及五項頂部分頁；手機可用標題手勢區換頁 |
| 低高度／200% 放大 | 寬度 ≥768px 且高度 ≤700px 時精簡留白、每側只保留最近一個收合夾；扣除頁首、分頁、標題、底欄與 padding 後，閱讀高度不足 280px 就切為文件原生垂直捲動，由 sticky 分頁導覽維持可達性 |

側夾最小高度 136px，標籤禁止換行、子元素不壓縮。低高度判定在文件模式仍以可用視窗空間計算，不依內容高度，避免反覆切換；底欄換行亦須重新量測。resize 自動夾限 scrollY 時不可覆蓋既存閱讀位置。

一般模式用 `100dvh` 分配頁首、分頁、共用資訊與剩餘舞台高度，各 grid／flex 容器正確設定最小高度，避免 body 與內頁同時出現主要垂直 scrollbar。低高度模式的文件捲動仍只展示一個分頁；切換 scroll root 時轉換並夾限目前閱讀位置。

正文不壓成縮小預覽；手機五個兩字頁名可在 320px 仍保持 44px 點擊寬度。視窗寬度變更時不重新選預設頁；舞台裁切只用於動畫外溢，不裁掉分頁焦點輪廓。

### 8. 可及性、焦點與網址

頂部採 `tablist`／`tab`／`tabpanel`，有可讀名稱、`aria-selected`、`aria-controls` 與 `aria-labelledby`。使用手動啟用模式：roving tabindex 控制焦點，方向鍵不立刻切頁，Enter／Space 才提交。側夾為有名稱的 `button`，不是第二份 tablist。

為讓頂部分頁按 Tab 後能進入目前頁內容，DOM 的主要操作順序為共用資訊／分頁 → 目前頁 → 側夾捷徑，視覺位置交給 layout 處理。不攔截內文或表單欄位的方向鍵。隱藏或退場頁使用 `hidden`／`inert` 等適合當下生命週期的機制，不能只靠 opacity=0。頁首的「跳至目前頁內容」入口直接聚焦當前 panel，不使用會被映射到指標頁的舊 `#dashboard-content` 錨點。

頂部點擊／鍵盤啟用留在對應分頁；側夾啟用後轉至同名頂部分頁，避免消失按鈕留下無效焦點。觸控手勢不強制跳鍵盤焦點；若焦點原本位於即將隱藏的內容，先轉到有效控制項。必要時以短訊息報讀「診斷，第 3 頁，共 5 頁」，不重讀整頁，亦不與 tab 的原生報讀重複。

Modal 保留原生焦點限制、Esc／關閉／遮罩與返回入口；開啟期間禁用背景導覽。瀏覽器歷史等外部導航發生時關閉失效 modal，焦點回目前分頁；不把遮罩上的橫滑當換頁。

網址以既有 hash 機制延伸，不加 router 套件：

| 輸入片段 | 解析結果 |
|---|---|
| `#indicators`、`#risk`、`#diagnosis`、`#evidence`、`#report` | 對應五頁 |
| `#overview`、`#dashboard-content` | 指標 |
| `#comparison` | 風險 |
| `#research` | 論證 |
| `#policy` | 報告 |
| 空值或不認識的片段 | 指標 |

明確換頁以 `pushState` 記一次目標；同頁不重複記錄。舊片段／無效片段正規化用 replace，不額外插入返回紀錄；popstate／hashchange 的同步不再次 push。網址只定位分頁，不是保存職業／快照的分享連結；重新整理使用預設職業，頁首必須明示，避免誤認已保存完整案例。

### 9. 元件邊界與資料交接

建議後續重構邊界（命名可在實作時調整）：

```text
App：選取職業、快照、refresh、共用 modal
└─ FolderWorkspace：頁序／目標／閱讀狀態
   ├─ FolderTabs：頂部選取與鍵盤
   ├─ FolderStage：外形、進退場與側夾按鈕
   └─ 分頁內容：指標／風險／診斷／論證／報告
```

沿用 React、TypeScript、Vite 與目前 SVG 圖示。先使用 CSS transitions／原生動畫能力完成少量狀態，不預設安裝 Swiper 或慣性捲動套件。若實作發現套件能明確改善可中斷動畫，另記依賴成本與非循環、wheel 禁用、可及性驗證，不只因使用者說 swiper 就引入套件。

此次純 UI 導航不需要新 API endpoint。`api.ts` 與 `verifiedSnapshot.ts` 保持原資料行為；切頁 handler 不呼叫 refresh 或報告生成。各頁可獨立呈現 loading／empty／error／stale，已有真實資料就維持顯示。

後端交接的必要資料仍包括（不在本次實作完成）：

| 交接項目 | 必要語意 |
|---|---|
| 職業分析 | 穩定 occupation ID、快照 ID、分類、實際人口／地域／期間、核定模型版本 |
| 指標與風險 | 真實值或 null、單位、可用狀態／原因、來源／方法／估算與信心；D 不併入 Risk |
| 診斷 | 已核對型態、引用指標 ID、替代解釋、適用限制；不足時有明確 unavailable 原因 |
| 論證 | evidence ID、機構／作者、原文連結與定位、核對狀態、支持的主張與限制 |
| 政策／報告 | 對應職業及快照、引用 ID、政策選項、限制與 KPI；生成服務狀態與失敗原因 |

前端不為五個分頁複製五份互相矛盾的資料契約。完整 API 凍結與資料補齊沿用既有 [後端交接草稿](../../../docs/BACKEND_HANDOFF_DRAFT.md) 與 [實作交接紀錄](../../../docs/FRONTEND_IMPLEMENTATION_STATUS.md)，此表僅標明新頁面的消費邊界，不宣稱服務已存在。

## Risks / Trade-offs

- [一次只看一頁，跨區比較較不方便] → 職業與期間始終可見；五頁直達，保留閱讀位置；不要求依序完成。
- [不循環的首尾畫面不對稱] → 如實表達沒有前／後頁；固定中央與側槽，不補假目標。
- [只有附近兩頁在側邊可見] → 全部五頁一直顯示於頂部，直接跳頁不需經過中間頁。
- [快速改選造成過期動畫覆蓋] → 單一目標、可中斷過渡、完成序號與取消清理；寫明連點測試。
- [手機誤觸／橫向圖表衝突] → 僅標題手勢區處理 swipe；wheel 與內文不綁換頁。
- [固定高度影響放大文字] → 320px、200% 及低高度驗收；必要時退回單頁文件捲動，保持可見導覽。
- [真實內容仍不完整] → 各頁以真實缺口驗收；不得把 UI 交付當完整政策模型交付。
- [舊提案描述與新布局相衝] → 此 change 核准後只替換布局與導覽決策，保留資料約束；實作階段同步相關舊文件，並記錄替代關係。
- [系統偏好減少動態效果] → 尊重偏好而非強迫播放；瀏覽器驗收需分別記錄一般／reduce 模式，不把 reduce 下的定格當動畫失敗。

## Migration Plan

1. 使用者審閱本文件與需求後，再啟動 apply；本輪所有實作 tasks 維持未勾選。
2. 開始實作時先保存並保留工作區既有修改，不重設分支；建立頁面元件但不改快照與公式。把與新布局衝突的舊文件段落標為被本案取代。
3. 先完成五頁內容重組、共用職業與非循環導航，再加入動畫、閱讀位置、響應式及鍵盤／手勢；沒有新資料也能驗收導航。
4. 遷移既有錨點測試並保留數值、缺值、刷新失敗與 modal 回焦點測試。新增邊界、直達、快速連點、wheel 不切頁、歷史與手機情境；執行 `npm run check`。
5. 以真實瀏覽器檢查 1440／1024／390／320px、低高度、200% 縮放與 reduced motion；一般模式記錄動畫，長內容只使用測試情境，不補造 production 報告。
6. 更新交接紀錄後交付使用者審閱。若布局驗收不佳，只回復本案的 UI／文件變更；保留先前淺色 Dashboard、原資料與其他人的修改。不需資料庫遷移，不包含雲端部署。

## Open Questions

沒有阻擋實作的操作決策。色票細微差異、檔案夾標籤凸起高度與 350–450ms 內的最佳時長留待視覺驗收微調；不改變非循環、wheel 只閱讀、五頁內容分工與資料約束。

## Implementation refinement（2026-09-12）

使用者要求安裝設計／動畫技能後優化。主要過渡仍為 420ms；經瀏覽器驗證，曲線微調為 cubic-bezier(0.32,0.72,0,1)。五個純裝飾外夾常駐，依目前中央／側槽位置做 transform 過渡，標題與內文不縮放；覆蓋先前互不連續的 scaleX(.08) 外框效果。導覽 active 顏色使用不可操作副本裁切同步。系統 reduce 仍直接定格，新增原因提示。觸控門檻、鍵盤行為、資料與非循環／wheel 決議不變。驗證見 docs/FOLDER_UI_VALIDATION.md；計畫見 plans/001-folder-continuity.md。
