## Context

動機與範圍見 [proposal.md](proposal.md)，可觀測行為見 [spec.md](specs/policy-decision-workflow/spec.md)。本變更跨越五頁內容、工作區導覽、分析狀態及列印，因此符合建立設計文件的條件。

探索基準為 `ce2695f`。現有 React／TypeScript 前端中，`App.tsx` 管理職業、快照及詳情；`FolderWorkspace.tsx` 管理五頁切換與閱讀位置；`FolderPages.tsx` 提供各頁內容。已有核對快照與資料不足狀態，但通用研究卡尚未提供逐項論點追溯，報告也尚未具備政策選取及完整文件預覽。這是待補能力，不是已完成宣告。

`define-youth-policy-dashboard` 已提出研究、政策與 KPI 方向，`add-folder-swiper-navigation` 定義導覽外觀。本變更只補內容間的任務流程，不複製完整指標模型、不覆寫其他變更。後續歸檔須檢查三者一致性。

## Goals / Non-Goals

**Goals:**

- 以共同上下文串起判讀、證據、政策與會議草稿，保留使用者直接切頁的自由。
- 將資料可用性與引用完整性轉成明確 UI 狀態，讓缺口可解釋且不污染報告。
- 提供可獨立測試的本機報告整理與列印，不等待 AI 生成 API 才能驗證閱讀流程。

**Non-Goals:**

- 不另建路由系統、後端文件服務、保存資料庫或新的第六頁。
- 不把既有待核對值轉為假真實數字，不在前端重算或改寫 Risk 公式。
- 不將國際研究機構名稱等同政策背書，不自行補寫未獲確認的因果判斷。
- 不保證 PDF 自動下載、PPTX 匯出或重新整理後保留選擇。

## Decisions

### 1. 以內容入口補足任務流程，不重做介面

保留五頁檔案夾、直條側邊分頁、動畫預設開啟與可關閉設定。使用者不必完成上一頁才能閱讀下一頁。

| 頁面 | 本次增加 | 主要下一步 |
| --- | --- | --- |
| 指標 | 緊湊摘要：分析對象、主要訊號、限制；沿用原指標區 | 查看職業風險 |
| 風險 | 選取職業的「查看判讀原因」 | 定位診斷 |
| 診斷 | 每項判讀區分觀測、推論、假說，連結相關指標與證據 | 核對這項判讀 |
| 論證 | 依判讀顯示研究關聯、適用範圍及限制 | 查看相關政策 |
| 報告 | 政策比較、納入會議草稿、完整預覽與列印 | 整理目前分析 |

來源、計算、清洗與估算維持次要詳情，不占據主閱讀區。摘要只使用核對快照或上游提供的文字與引用；前端格式化不等於產生政策論述。

替代方案：改成強制步驟精靈會阻止快速查核；增加總覽頁會改變已確認的五頁架構，均不採用。

### 2. 導覽意圖包含內容識別，不只切換分頁

建議由工作區接收分頁、職業／分析鍵、內容 ID 及請求序號。先讓目標頁成為可互動頁，待內容掛載後才定位並聚焦標題；不直接聚焦背景的 inert 面板。這是內部建議，不是後端契約。

既有分頁切換保留閱讀位置；只有使用者明確點擊內容入口才定位指定項目。快速連點或上下文變更取消舊定位。目標不存在時顯示缺口並停在對應頁標題，不任意跳到另一個證據。

證據詳情沿用既有單層詳情容器，記錄觸發元素與捲動位置；關閉或 Escape 恢復焦點。觸發元素已不存在則回到頁標題。新增動畫遵守減少動態偏好，避免每次開詳情都移動整個檔案夾。

替代方案：單純 DOM selector 捲動可能命中隱藏分頁或過時職業，不採用；不為此次內容入口新增可分享案件 URL。

### 3. 用明確引用圖及轉接層隔離後端差異

建議建立前端顯示模型與驗證／轉接層，將已核對快照與未來 API 轉成相同語意結構，不直接讓頁面依賴舊 API 欄位。來源 ID 能解析、關聯有理由與核對狀態合格，三者都成立才是可用依據。

一筆研究可在不同判讀中有不同關係；支持／反證／限制／背景放在關聯上，不放在研究的全域屬性。直接引文和整理摘要分開，引用定位與原文 URL 原樣保留。

以下為**建議交接語意**，欄位名稱與 enum 尚非已定稿 HTTP schema：

| 物件 | 必要語意 | 前端責任／不足處理 |
| --- | --- | --- |
| 分析 | analysisId、modelVersion、職業代碼／名稱／分類版本、目標及實際族群、地區、各來源期間、發布／核對時間 | 驗證上下文，區分目標 18–35 與實際資料年齡 |
| 指標 | 指標 ID、值／單位／尺度、來源引用、exact／estimated／proxy、信心與可用狀態 | 格式化既有值，不重算公式；缺值不當零 |
| 判讀 | claimId、文字、觀測／推論／假說、indicatorRefs、evidenceRelations | 顯示判讀和依據，不由前端猜測診斷類型 |
| 研究 | evidenceId、來源類型、標題、作者／機構、日期、摘要、可選原文引文、URL、定位、適用範圍、限制、核對狀態 | 安全顯示 HTTP(S) 連結，不執行 HTML，不製造引文 |
| 研究關聯 | claimId、evidenceId、關係類型、關聯理由、適用性核對結果 | 關聯缺漏顯示缺口；來源存在不自動背書 |
| 政策 | optionId、適用職業、問題／措施／機制、條件／合作方／成本或負擔、效益、KPI、限制、claimRefs／indicatorRefs／evidenceRefs、適用性狀態 | 比較、選取；缺必要依據不可納入草稿，次要欄位未知則明示 |
| 可用性 | loading／ready／partial／unavailable／stale／error、原因與可重試能力 | 沒有重試能力就不提供假重試；舊內容保留真實時間 |
| 報告資訊 | 可用章節、來源生成時間（若有）、引用及版本 | 本機另記 assembledAt，不冒充後端 generatedAt |

前端負責呈現、查核入口、上下文隔離、選取與列印。後端／資料負責人負責抓取、清洗、分類對齊、年齡估算、公式計算、研究核對、政策內容及一致版本發布。API 端點、驗證方式與更新排程在串接前對齊；本文件不聲稱它們已實作。

替代方案：UI 自由猜測欄位或來源適用性會把契約錯誤藏進畫面，不採用。

### 4. 政策比較與選取採目前使用階段狀態

二至三個有效選項是常見呈現，不是資料生成數量要求。桌面最多三欄，更多選項繼續排列且皆可存取；小視窗改為單欄。所有選項使用相同欄位順序。只有一個時呈現詳情，沒有時顯示原因及上游提供的有效監測方向。

選擇鍵建議由 analysisId、occupationCode 與 optionId 組成；若有職業分類版本一併納入。初始為空，使用明確 checkbox 與「納入會議草稿」，同一頁可取消。以記憶體保存，不新增 localStorage 資料保存承諾。返回同版本可恢復，但新版本不自動遷移，並提示重新確認。

有已確認的政策機制與必要引用才可選；成本或 KPI 目標未知可標示待確認，不等於所有欄位都必須完整才可討論。選取是討論意願，不是批准或演算法排序。

替代方案：預選所有政策會讓使用者未確認便輸出提案；跨版本自動沿用易導致舊政策搭配新證據，均不採用。

### 5. 報告使用純資料整理及固定快照

將「整理目前分析／預覽會議草稿」與既有「產生完整政策報告」服務分開命名。前者純粹整理已有內容，後者在 AI 後端未具備能力前仍不可用，不以本機預覽冒充成功。

建議由獨立整理器產生不可變的報告物件，包含當下上下文、內容與必要引用副本，而不是讀取目前 DOM。預覽放在報告頁內的完整文件閱讀區，不新增主分頁。狀態建議如下：

| 狀態 | 條件 | 使用者看到 |
| --- | --- | --- |
| 政策討論草稿 | 有選取且必要依據可用的政策 | 選取政策、證據、限制及人工審閱提示 |
| 監測摘要 | 未選政策或不足以提出政策，但有可核對分析內容 | 可用發現與資料缺口，不稱完整政策提案 |
| 無可整理內容 | 沒有可核對分析內容 | 明確原因，停用預覽及列印 |

Risk 不完整不代表完全不能監測；反之有分數不代表已有政策依據。引用錯誤須列出受影響項目並排除不可用政策，不偷偷改連結。引用清單依實際納入內容彙整且去重，保留逐段引用識別與定位。

同一分析內各來源期間可以不同；保留其差異與限制。新版快照先驗證完整關聯再原子替換主畫面。已開啟預覽保持舊版並提示更新，使用者明確重建才更換；切換職業關閉預覽，遲到回應不影響新上下文。

替代方案：即時從頁面 DOM 複製會漏掉折疊或捲動內容；讓預覽隨更新自動變動會失去會議版本可追溯性，均不採用。

### 6. 列印獨立文件結構，驗證真實瀏覽器結果

報告以語意化文件結構呈現，列印樣式移除檔案夾高度、overflow 及所有操作元件，只輸出報告。A4 直式、可換行 URL、長表格重複表頭、圖表及短卡片避免跨頁；超過單頁的段落允許合理分頁，不使用全區禁止分頁而產生空白或裁切。

動作標示「列印／另存 PDF」。呼叫瀏覽器列印不代表檔案儲存成功，取消後仍停在預覽，不顯示假成功通知。印刷不依賴背景色保留語意。使用真實瀏覽器列印預覽驗證，不只看螢幕截圖或單元測試。

替代方案：伺服器 PDF 與 PPTX 可之後獨立提案，本期不新增依賴或服務。

### 7. 分開驗收前端功能與真實決策案例

第一道驗收使用隔離的測試 fixture 驗證有／無資料、0／1／多政策、缺引用、版本競態、長內容與縮放。fixture 不進入正式資料回退流程；通過只代表 UI 行為可用。

第二道驗收至少一個真實職業可完成「指標 → 判讀 → 相關證據 → 政策 → 可列印草稿」，並核對每個引用與限制。缺真實政策資料時列為待交接，不能把第一道驗收當成完整 Demo 已完成。

評估重點對應先前核對的完成度、主題契合、技術可行與資料應用方向；不將主觀 Demo 分數當成官方評審結果或通過門檻。

## Risks / Trade-offs

- 研究可信但不適用此職業 → 逐項關聯理由、適用範圍及核對責任，不以機構聲望代替證據。
- 真實資料仍不足 → 前端可先測行為，正式流程驗收維持未完成，不填假資料。
- 新版本與舊政策混用 → 上下文鍵、原子快照、固定報告與遲到回應防護。
- 短視窗／大字體讓固定容器卡住 → 單欄閱讀、可達捲動及原生 200% 驗收，不只模擬 CSS zoom。
- 印表機及瀏覽器差異 → 先列明實測瀏覽器、紙張及結果；不承諾跨環境像素一致。
- 功能增多再度使畫面擁擠 → 摘要精簡、證據詳情按需展開、維持單一主要下一步。

## Migration Plan

1. 在後續實作變更建立顯示模型、引用檢查與隔離測試資料，維持現有快照讀取。
2. 加入內容導覽與證據追溯，再做政策比較及選取；每段有各自測試。
3. 加入固定報告整理器、預覽與列印，最後補摘要與全流程驗收。
4. 後端欄位對齊後由轉接層接入，不變更模型公式與既有正式資料；不相容回應明示不可用。
5. 記錄真實案例、瀏覽器及印刷驗收，再決定對外展示；本規格不執行部署。

不需要資料庫遷移。若後續實作需回退，回退該功能提交即可恢復既有五頁閱讀；不可連帶回退或覆寫團隊資料與其他分支變更。

## Open Questions

- 串接前由後端確認正式端點、欄位拼字、驗證方式與刷新排程；不影響此處的語意需求與前端轉接設計。
- 由團隊指定正式研究核對及政策適用性的簽核負責人，並選定第一個完整真實案例；未完成前不能宣告真實流程驗收通過。
- 列印驗收需記錄現場實際瀏覽器版本；本期預設以開發使用的 Chromium 系瀏覽器驗證，其他引擎另記支援情況。
