## Context

見 `proposal.md`。已讀新 repo 的 OpenSpec 設定、既有 `docs/DEVELOPMENT_SPEC.md` 與兩份附件；目前沒有前端程式、測試或可用資料檔。使用者負責前端，要求先需求與 Demo，再向後端交接；最新回覆明確要求真實數據與核對來源。

## Goals / Non-Goals

**Goals:** 用同一職業與分析版本連起三區，先建立可審閱的閱讀流程；將資料缺口納入畫面與驗收；讓後續資料來源能由版本化真實檔案換為 API。

**Non-Goals:** 本文件不實作 ingestion、AI 搜尋或雲端服務。本期閱讀體驗不依賴每次即時生成。後端自動更新列入交接；自由搜尋、手動 refresh 與按鈕生成不列前端必備。

## Decisions

### 1. 一頁式 Dashboard 與單一職業脈絡

頁首提供三區錨點，職業列表／卡片用於選取瀏覽对象；指標、證據及政策共同使用選取職業與分析版本。相較三個各自選擇職業的頁面，共用脈絡能減少混讀。首屏優先顯示分析問題與訊號，技術處理細節放詳情。

UX 使用單一詳情面板，桌機在側邊、窄螢幕全寬，支援鍵盤與還原焦點。避免多層面板堆疊，使返回來源位置簡單可預測。

### 2. 明確區分資料值與資料狀態

指標資料除了值還攜帶單位、來源、期間、方法、缺值原因。畫面對 null 顯示原因；不能只用一組 number 型別表示所有狀態。A/B/C/H 的共同 0–1 範圍用長條展示，D 的占比及成長率獨立呈現，避免同尺度雷達造成誤解。

Risk、分級及型態由核定結果提供，formula_version 對應實際方法。新模型記 v0.4 候選：H 為整體新登記求才的下降 clip；D 保存原始占比與百分位。候選級距／矩陣完整列於前端需求稿，核定前不自行套入正式數值；D 排名集合及 B 大類聚合仍需方法補充。

### 3. 真實資料可先以版本化檔案承載

建議資料存取層將來源與元件分離：讀取已核對的真實資料檔或未來 API，都轉為相同 view model。React／TypeScript／Vite 可沿用既有規格的技術提案，實際建置留待實作。

使用者已同意正式後端自動取得、前端讀 API 的流程；開發先使用已核對真實快照。自動更新按來源週期運作，先驗證再切換完整分析版本；不因使用者切職業或開頁就重新抓所有外部來源。更新失敗保留前次成功結果與過期原因。合成 fixture 僅測試錯誤，不會成為 production fallback。

2025 為 Risk 候選基準期，D 採實際最新快照。跨期結果保存兩個版本與日期，不能替舊 Risk 改時間。首批三個職業大類可用來瀏覽；D 百分位的比較母體必須獨立定義，不依 UI 篩選。細職業僅作有核對映射的案例說明。

### 4. 證據及政策使用 ID 連結

研究摘要、原文與政策引用分開保存。政策對應明確 evidence_id 與 indicator reference；先檢查可解析再展示。與直接把自由文字塞進卡片相比，ID 可使點擊來源定位一致，也便於後端交接。

正常政策內容以 2–3 張設計，容器允許較少或空；筆數上限可之後決定。KPI 沒有目標值時顯示待試辦訂定，資訊不足時僅顯示缺口。

## Risks / Trade-offs

- [H 母體改變] → 已核對官方有 2013–2025 歷史，但要清洗且明示整體求才；新人 H-entry 另案。零基期或缺必要值則不計 Risk。
- [附件引用尚未逐篇核對] → 將來源核對列前置任務；不把附件或 NotebookLM 編號當已驗證證據。
- [18–35 為估算，22–25 為政策情境] → 以實際資料口徑標示，不假裝可精確下鑽。
- [模型跨年與分類映射未定] → 每項保留期間、方法及 coverage；無核定規則則 unavailable，不自由猜測。
- [舊開發文件不同] → 保留原文及差異表；自動更新已定案，其他不相容模型不混用。
- [先前端但要求真實數據] → 需在 Demo 驗收前完成必要資料準備，不能等 API 開發時才找資料。

## Migration Plan

新 repo 無既有產品可遷移。本輪僅新增需求與提案文件，不覆寫舊規格、不移植舊 repo。

後續以真實資料檔完成驗收後，再將資料存取換成正式 API；對照相同資料案例驗證指標、來源与政策一致。部署及回滾方案由後端整合阶段另定。

## Open Questions

可延後且不影響核心規格的項目：品牌最終名稱、政策卡正常顯示 2 或 3 筆、長條圖視覺細節。三個候選大類與 2025 基準仍以真實資料對齊核對為驗收條件。

完整模型案例在缺必要資料或核定方法時不可宣告完成。後端排程頻率及過期上限在交接時確定，不影響已確認的「使用者無須操作更新」行為。
